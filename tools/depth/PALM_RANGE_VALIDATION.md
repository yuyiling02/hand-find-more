# 手掌伸收验证

进入 RehabDemo 播放模式，在 F1 面板选择「手掌伸收」。先采集舒适的收手位置，再向摄像头伸手并采集舒适的伸手位置。采集时保持同一只手完整入镜，掌心或手背朝向摄像头。

画面上下是默认模式。「模型深度」用于对比并启动 Python 服务。「手掌伸收」使用 MediaPipe 数据在 Unity 内计算。

## 已验证

- 使用 Unity 6000.6.5f1 的 C# 编译器和工程编译参数，运行时代码及编辑器回归入口编译通过。
- 合成关键点回归使用实际的 Unity 数学程序集独立运行通过，覆盖方向、行程、镜像、画幅比例、倾斜补偿、侧掌迟滞、异常校准、时间戳、丢手恢复、切换手和增益限幅。
- Unity 批处理在运行回归入口前退出。可在 Unity 内通过菜单 Rehab Demo → Validate Palm Range 运行同一套用例。

## 待摄像头验收

打开 F1 的「显示手掌诊断」和「记录采集时间和前后行程」。日志包含帧采集与位置更新时间、几何耗时、滤波前目标、输出行程及暂停原因。性能采样后可关闭日志，避免持续输出影响手感。

| 场景 | 目标 |
| --- | --- |
| 舒适范围内连续伸收十次 | 方向一致，每次覆盖至少 80% 行程 |
| 静止十秒 | 行程 P95−P5 不超过 5% |
| 原地握拳、捏合、适度翻掌 | 行程偏移不超过 10% |
| 快速伸收 | 几何耗时 P95 小于 1 ms，目标与输出过中点的时间差以 80 ms 为目标 |
| 实际训练 | 各视角检查方向和可达性，完成取放杯子及开关微波炉门 |

摄像头动作与实用性指标尚未测量。保持默认使用画面上下，待本机对比后再决定是否切换。

## 2026-11-17：伸收仍不跟手的排查

- 模型深度模式的归一化行程改为一层 One Euro（2 Hz / beta 1 / dCutoff 1）后限速；HandFrameBus 不再对该 Z 叠加位置滤波。横向与画面上下模式不变。结果无效时保持当前 Z，恢复时从当前位置初始化。
- F1 新增「记录 30 秒伸收诊断」，三种模式都可用。内存缓冲数值，30 秒后或手动停止、退出播放时保存；不保存摄像头画面。
- Unity 编辑器日志：项目 Logs/ForwardControl/forward-*.csv；构建版本位于 Application.persistentDataPath/ForwardControl。
- 使用方法：在所测模式校准后开始记录；静止 5 秒，保持画面高度、掌心朝向摄像头，舒适范围内伸收 5 次。记录期间不要切模式或重校准。可以另录画面上下模式作为对照。
- CSV 的 model depth / palm scale 字段只有对应模式正在运行时才有诊断意义；无新手帧时关键点字段是上一帧，须结合 new_hand、tracked 和时间戳判断。
- 重点对比 target、controller_position、table_position：输入目标没变化不能靠输出滤波解决；目标变化而输出滞后才是控制链问题。深度原始值是否单调必须用真实动作判定。
- 已通过：Unity 项目引用下的 Roslyn 编译；原几何回归；受控 Z 不重复滤波、X 继续平滑、暂停保持 Z、原模式滤波保留的回归。
- 待验证：Unity 内按钮与 CSV 落盘、真实伸收幅度及延迟、静止抖动、握拳/捏合干扰、训练可达性。未宣称效果已达到画面上下模式。

## 单手校准修复
左右手分类变化不再自动清除PalmRange校准；实际换手需手动重新校准。每端点10秒期限，至少15个有效样本并覆盖1秒；超过1秒无有效样本重置本端点批次，第二步重试保留第一步。采集角度仍不超过45度，年龄不超过250ms。新增样本数/阻断/失败字段与CSV分类信息。Roslyn编译与合成回归已通过；真实摄像头与新面板视觉检查尚未完成。
